The server paints Bluesky profiles and threads signed out, from the public AppView (`BLUESKY_PUBLIC_APPVIEW`, no redirects followed), when `BLUESKY_SSR=1` is set; without it nothing changes, and the SDK is not loaded. With it, every reader gets these pages for Bluesky routes. Route rules follow spec 8.4: `@name@host` is Mastodon, `@did:…` and a dotted `@name` are Bluesky; the server decodes the segment as the client does. A bad handle, DID or record key gets a 404 page and no request. The server runs moderation with the signed-out defaults. An author shows signed out only when its labels were read and none is `!no-unauthenticated`: a missing or partial author, or labels that are null or not an array, is hidden, at every place (profile, feed item, reposter, quote, reply parent and root, thread post, record card creator). Their name, handle, avatar, banner, bio and text are not in the response at all; the page shows "This account asked to be seen only by signed-in readers." A page opened by DID shows the handle in the address bar after hydration. Mastodon profile and post links never use a bare dotted `/@name`: they take a known host, then the account URL's host; with neither, a profile links to a search, and a post links to its own page or is not a link. The reader check no longer sends Bluesky posts to a Mastodon server.
